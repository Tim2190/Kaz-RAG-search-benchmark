# Kaz-RAG-Search-Benchmark

**Доказательный бенчмарк: почему базовый поиск «слепнет» на казахском языке — и как морфологическая нормализация (стеммер) это чинит.**

![Сравнение 5 систем](results/systems_ndcg.png)

> На запросах с другой словоформой базовый поиск (BM25) почти слепнет
> (ndcg@10 = 0.18). Казахский стеммер возвращает его до **0.45** — прирост
> **+145%** (recall@1 **+200%**), статистически значимо (p = 0.0005).
> BM25+стеммер (0.599) **обгоняет Dense LaBSE** (0.412) в среднем.

## Заголовочный результат

Корпус: **8 370 пассажей** (казахская Википедия) · Запросы: **300** (100 сущностей × 3 категории).
Система: **BM25 (Okapi)**. «До» — без нормализации; «После» — токены корпуса и
запроса приводятся к основе [казахским стеммером](https://kazakh-stemmer-590833642796.europe-west1.run.app).

Парный bootstrap, 10 000 ресэмплов, n=300 запросов:

| категория (ndcg@10) | До | После | Δ | прирост | значимость |
|---|---|---|---|---|---|
| **inflected** (другая словоформа) | 0.627 | **0.727** | +0.101 | **+16%** | p=0.0017 ✅ |
| **ВСЕ** | 0.690 | **0.754** | +0.064 | **+9%** | p=0.0001 ✅ |
| natural (обычные вопросы) | 0.703 | 0.772 | +0.068 | +10% | p=0.006 ✅ |
| vocabulary-gap (синонимы) | 0.741 | 0.764 | +0.023 | +3% | p=0.21 ✗ |

> Vocabulary-gap не значим — ожидаемо: стеммер лечит морфологическое несовпадение,
> а не семантические пробелы. Это честный, теоретически корректный результат.

**Почему так:** 800 статей дают **102 408 уникальных словоформ** — агглютинативная
морфология казахского взрывает словарь, и точное совпадение слов перестаёт работать.
Стеммер сводит формы к основе (`Бакуде → баку`, `теңіздерге → теңіз`) и поиск прозревает.

Полная сводка с выводами — в [`results/RESULTS.md`](results/RESULTS.md).

## RAG end-to-end: эффект стеммера на 3 моделях

Стеммер поднимает **попадание контекста 0.467 → 0.667** (+43%) — нужный пассаж
доходит до LLM в 1.4 раза чаще. Проверено на трёх моделях растущей силы:

![RAG: эффект стеммера по моделям](results/rag_models.png)

| Модель | Accuracy (без → со стеммером) | Δ acc | Δ галлюцинаций |
|--------|:---:|:---:|:---:|
| Granite-2B | 0.250 → 0.267 | +0.017 | −0.033 |
| Granite-8B (4-бит) | 0.350 → 0.417 | +0.067 | −0.067 |
| **Qwen2.5-7B** (4-бит) | **0.400 → 0.500** | **+0.100** | −0.017 |

**Главный паттерн:** прирост accuracy от стеммера **растёт с компетентностью модели**
(`+0.017 → +0.067 → +0.100`). Улучшение ретривала одинаковое для всех трёх; более
сильный генератор конвертирует больше «правильного контекста» в правильные ответы.
Qwen2.5-7B — лучшая end-to-end система: вместо выдумки она отказывается (`Ақпарат жоқ`),
а стеммер превращает эти отказы в правильные ответы.

> ⚠️ **Честная оговорка:** end-to-end дельты измерены на n=60, один прогон, **без**
> bootstrap-валидации (в отличие от результата по ретривалу). Направление устойчивое и
> механизм понятен, но для строгого статистического вывода нужен больший набор запросов.
> Это **продемонстрированный тренд**, а не доказанный; а вот ретривал-прирост, который
> его порождает (0.467 → 0.667), измерен прямо и твёрдо.

## Методология

- **Корпус.** 800 случайных статей казахской Википедии из готового дампа
  [`wikimedia/wikipedia`](https://huggingface.co/datasets/wikimedia/wikipedia)
  (Hugging Face) → чистка → нарезка на пассажи ~120 слов → фильтр языка
  (отсев не-казахских фрагментов) → **8 370 пассажей**.
- **Запросы.** 20 сущностей (страны, города, люди, понятия) × 3 категории:
  - `inflected` — ключевое слово в косвенном падеже (стресс на морфологию);
  - `vocabulary-gap` — синонимы/перифраз (стресс на семантику);
  - `natural` — обычные вопросы.
  Для каждого запроса известен эталонный пассаж-ответ (qrels).
- **Системы.** BM25 (лексический baseline) ± казахский стеммер. В разработке —
  dense-эмбеддинги: IBM Granite, Google LaBSE, multilingual-e5.
- **Метрики.** Recall@{1,5,10}, MRR@10, nDCG@10 + статистическая значимость
  (парный bootstrap, 10 000 ресэмплов).
- **Честность.** Baseline настроен добросовестно; выигрыш показан как дельта на
  одинаковых условиях. Стем-кэш закоммичен — цифры воспроизводятся «как есть».

## Как запустить у себя (и проверить, что цифры настоящие)

```bash
git clone https://github.com/Tim2190/Kaz-RAG-search-benchmark.git
cd Kaz-RAG-search-benchmark
pip install -r requirements.txt

# 1. Прогон «До» и «После» (стем-кэш уже в репозитории — сети не требует)
python -m src.eval.run_benchmark --stemmer identity --out results/bm25_identity.json
python -m src.eval.run_benchmark --stemmer kazakh   --out results/bm25_kazakh.json

# 2. Сравнение с дельтой и приростом + график
python -m src.eval.compare --before results/bm25_identity.json \
    --after results/bm25_kazakh.json --chart results/before_after.png

# 3. Статистическая значимость
python -m src.eval.significance
```

Пересобрать корпус с нуля (Hugging Face) и прогреть стем-кэш — см. [`PIPELINE.md`](PIPELINE.md).

### Тесты

## Структура

```
src/
  scraping/    # сбор корпуса (wiki_scraper — дамп HF; news/gov — запасные)
  corpus/      # чистка, нарезка на пассажи, фильтр языка
  queries/     # запросы + qrels, загрузка датасета
  retrieval/   # bm25 (лексический) + dense (эмбеддинги)
  preprocess/  # казахский стеммер (HTTP-клиент + кэш), токенизатор
  eval/        # метрики, прогон бенчмарка, сравнение, значимость
data/
  corpus/      # corpus.jsonl — 8 370 пассажей
  queries/     # queries.jsonl — 60 запросов с qrels
  resources/   # stem_cache.json — кэш стеммера (102k слов)
results/       # метрики, график, сводка
tests/         # 43 теста
```
