## Шаг 1 — валидация запросов ✅ ВЫПОЛНЕНО

дальнейших прогонов; raw-наборы `synonym_queries.jsonl` / `_v2.jsonl`
оставлены как исторические (до валидации).

## Шаг 2 — один прогон на Kaggle (~30–40 минут машинного времени)

Notebook: `notebooks/sprint3_all_runs.py` (GPU T4 + **Internet ON**).
Считает все 11 систем на 127 валидированных запросах и сохраняет полные
выдачи: `/kaggle/working/sprint3_runs.json` (~5–10 MB). Скачайте и пришлите
в чат.

## Шаг 3 — pooling-разметка релевантности (~1–2 часа, главный шаг)

Из присланного runs-файла я соберу `annotation/pool_relevance.tsv`:
для каждого запроса — объединение топ-10 всех систем (обычно 15–25
кандидатов на запрос). Назначенный gold уже помечен `RELEVANT=1`.

Ваша задача: для остальных кандидатов поставить в колонке **RELEVANT**
`1` (пассаж отвечает на запрос) или `0` (не отвечает). Это стандартный
pooling из IR — после него метрики перестают занижаться из-за
неразмеченных релевантных пассажей.

## Шаг 4 — финал (автоматически)

```
python -m src.eval.sprint3_rescore \
    --runs results/sprint3_runs.json \
    --pool annotation/pool_relevance.tsv \
    --out results/sprint3_final.json
```

Выдаёт три таблицы (passage / article / pooled) с CI95 — честные финальные
цифры для статьи.
